## [Unreleased]

### Added

- `Events.writeDestination`: a link's destination as CommonMark reads it, the URL it means (escapes and references resolved, `mailto:` and `http://` supplied as the HTML writer supplies them), with nothing escaped for HTML: for a terminal's link or a program's lookup. `html.writeDestination` is it escaped for HTML.
- `Events.work`: the steps the inline pass has taken, every byte and item it read, each scan's bytes included; with the block pass's (`Document.stats`), what the pathological tests hold to 48 steps per input byte. cmark's and cmark-gfm's pathological inputs, 26 of them, and 10 shapes of datapad's own extensions are tests, each held to that bound and to the HTML cmark's test expects (their BSD 2-Clause notice in LICENSES/cmark-BSD-2-Clause.txt). A fuzz target over any bytes, or Markdown mutated, under any extensions and expansion limit: every span, nesting and order, the work bound, and `ExpansionTooLarge` exactly when a recount of the stream passes the limit, checked against a planted fault. `bay bench` rows (`bench/main.zig`): parsing and HTML over the CommonMark spec, the spec at 16 MiB, any corpus given (`--corpus name=file`), and the pathological shapes at three sizes; CI compiles them. The README's usage (`examples/usage.zig`, run with the tests), and docs/design.md.
- The package: its build, the `datapad` module on aegis and xenoglyph, and its development under preflight's gate.
- Its vocabulary: `Span` (`u32` offsets, `of` its text), `Limits` (input, depth, blocks, references, expansion) and `Options` with `Extensions` (`commonmark`, `gfm`, wikilinks, front matter).
- The block pass: `Document.parse` reads a text (an `aegis.input.Untrusted` borrowed until `deinit`) once, a line at a time, into the block table, CommonMark 0.31.2's block structure: block quotes, lists and their items (bullets, ordered starts, the rules for interrupting a paragraph, tight or loose), paragraphs with lazy continuation, ATX and setext headings, thematic breaks, indented and fenced code (info strings), the seven kinds of HTML block, and tabs taken in part as §2.2 counts them. Each block's record gives its kind, depth, span from its first marker to its last byte and, for a leaf, its content lines. Link reference definitions go to the label table, matched by labels collapsed and Unicode case folded (`find`, `normalizeLabel`), the first of each label resolving. `lineOf` gives an offset's line and column. Every refusal is a limit, named (`InputTooLong`, `TooDeep`, `TooManyBlocks`, `TooManyReferences`) with its offset in a `Limits.Diagnostic`; nothing recurses, and the pass's work is linear in the text, which tests hold it to on the shapes that make block parsers quadratic. A property over generated text holds the table's guarantees (spans nested and in order, lines inside their blocks, legal nesting, the label table's first definitions, linear work), checked against planted faults.
- The HTML writer: `html.write(writer, &events, options)` writes a document's events as CommonMark's reference HTML, as cmark writes it: the spec's HTML for each of CommonMark 0.31.2's 652 examples, which the tests read from the spec as it is published (testdata/commonmark, CC BY-SA 4.0) and compare byte for byte. Safe by default: raw HTML is written as `<!-- raw HTML omitted -->`, and a link or image whose destination runs script (`javascript:`, `vbscript:`, `file:`, `data:` other than a PNG, GIF, JPEG or WebP image) gets an empty one; `Options.unsafe` writes both as they are. Destinations are percent-encoded after their escapes and references are resolved (`html.writeDestination` gives the URL a destination means), text is escaped, and U+0000 and ill-formed UTF-8 are written as U+FFFD. `Options.soft_break` writes a soft break as a line ending, a space or `<br />`.
- The events: `Events.init(gpa, &document)`, or `Events.initBuffer(&document, buffer)` in the caller's memory of `Events.memory(&document)` bytes, gives a document as a stream of `Event`s, each 32 bytes (`Node`, `Link`; the layout checked at compile time) with its exact span: each container entered and exited around what it holds, a code block's and an HTML block's lines (`spaces` before a line a tab was taken from), and a paragraph's and a heading's inlines, CommonMark 0.31.2's §6: code spans, backslash escapes, entity and numeric references (their code points), autolinks and email autolinks, raw HTML (a piece per line, sharing the tag's span), hard and soft breaks, emphasis and strong emphasis by the spec's delimiter algorithm (`openers_bottom`, the rule of 3), and links and images in all four forms (inline, full, collapsed, shortcut), no link holding another. A link's title and label are `Events.title` and `Events.label`, read while its leaf is. `next` never allocates: one leaf's inline pass runs in memory the block pass sized from the largest leaf, its labels normalized in fixed memory. It fails only past `Limits.expansion`, the bytes reference links reproduce, with the offset in the diagnostics, and every later call fails too. Each construct's scan is bounded or remembers what it found, so a leaf of openers with no closer (backticks, comments, quotes, brackets) costs its length. A property over generated text holds the stream's guarantees (nodes balanced, spans in bounds, nested and in order, text never crossing a line), checked against a planted fault.
- GitHub Flavored Markdown's extensions, each on by its `Extensions` field: `tables` (pipe tables as `table`, `table_head`, `table_row` and `table_cell` events, each cell with its column's alignment, `\|` a pipe in a cell, code spans included), `strikethrough` (one or two tildes, by the delimiter algorithm), `task_lists` (`[ ]` and `[x]` at a list item's start, a `task` event), `autolinks` (`www.`, `http://`, `https://` and `ftp://` links and e-mail addresses linked bare, trimmed as cmark-gfm trims them) and `tagfilter` (the HTML writer writes the `<` of GFM's disallowed tags as `&lt;`). `Document.extensions` holds the syntax a document was parsed with. The writer gives the GFM spec's HTML for each of its 24 extension examples, which the tests read from the spec as cmark-gfm 0.29.0.gfm.13 publishes it (testdata/gfm, CC BY-SA 4.0), and CommonMark's 652 as before.
- Wikilinks and front matter, each on by its `Extensions` field. `wikilinks`: `[[target]]` and `[[target|label]]` (and `![[...]]` for an image) are links of kind `wiki`, the target their destination as written; a target alone is the link's text, not read as Markdown, and a label is read as a link's text is, over lines if it runs on. A wikilink is one up to its first `]]` with no other bracket before it, its target on one line and not blank, its label not empty; it is read before the brackets around it, so no link holds one, and a code span or raw HTML in its label that runs past the `]]` leaves it text. The HTML writer makes it a link to its target, percent-encoded. `front_matter`: a text that starts with a `---` line closed by a `---` or `...` line (YAML), or a `+++` line closed by a `+++` line (TOML), has that block as its first, a `front_matter` node whose events are its body's lines; `Document.frontMatter` gives its `Format`, its span and its body's. datapad reads neither language. An opening line never closed is Markdown. The HTML writer leaves front matter out. The events property draws every set of extensions, wikilink pieces and front matter heads, checked against a planted fault.
- Character scanning (`scan`): CommonMark's ASCII and Unicode punctuation and whitespace, the Unicode classes by xenoglyph's General_Category; the code points either side of an offset; columns with tab stops of 4, a tab taken in part leaving the rest; and the 2125 HTML5 named character references CommonMark reads, a table `tools/generate.zig` writes from WHATWG's entities.json behind a minimal perfect hash, which the tests write again and compare byte for byte.

### Changed

- Pins aegis f52eabe, still 0.2.4, and xenoglyph ab4d381 on it, the one aegis the family builds on; development on preflight's ci-standard 158c176 and shakedown 327bc61.
- datapad's own development holds it to the family's policy: `"policy": "family"` in ci/preflight.json, beside the hardened profile ci/workflow.json already declares; the hardened and hardened-tsan legs pass. `zig build check-consumer` builds ci/consumer.zig as a project that depends on datapad alone would, and runs among the gate's extra checks. .github/workflows/ci.yml, generated (`bay dev generate`), runs that gate on GitHub: datapad had none. .gitattributes keeps every file LF on every platform: a Windows checkout wrote the spec texts with CRLF, and the spec tests found none of their examples.

### Fixed

- Inputs that took time growing with the square of their length now take time linear in it: a run of images (`![[]()` repeated) walked the bracket stack down to the last link for each link; an unclosed run of `(` in destinations (`[a](b` repeated) was read to the leaf's end for each link, and a destination's parentheses now nest at most 32 deep, as cmark's; an emphasis closer that found no opener left a floor a later match could take off the stack, after which each look back ran to the bottom (cmark's issue #389); a URL's trailing parentheses were counted again for each one trimmed; and each blank line under deeply nested lists walked every open list again.
- A GFM table's delimiter row needs no pipe, and may have a line tabulation or form feed around its hyphens, as cmark-gfm reads it: `bbb` over `-` and a line tabulation is a table of one column. A row of hyphens alone under a paragraph is still a setext heading's underline.
